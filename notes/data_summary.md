## Location occupancy: interpretation and rate limits

Each row is a company's tenancy in a property over `fromDate` to `toDate`, not a property's occupancy percentage. `propertyId` joins commercial-property `id`; `tenantLocationId` joins company-detail `id` (null means unknown tenant).
`toDate` is null on 11179/74093 rows (still in place per the model doc). For an as-of analysis, apply `fromDate`/`toDate` windows rather than summing all historical tenancies. Use `moveInDate`, not lease sign date, for absorption.
Occupied area is `sum(spaces[].squareFeetOccupied)` for the appropriate tenancy window. This is not a vacancy numerator, and marketed listing availability cannot substitute for vacant area.
No direct, reliable per-property occupancy/vacancy rate is supplied by this file alone. A derived occupancy share requires complete current tenant coverage, non-overlapping/deduplicated spaces, and a compatible known property RBA (retail GLA) denominator; audit these before deriving a vacancy complement. For apartments, `propertyApartment.vacancyPercent` is a separately reported property-level figure; `numUnitsAvailable / totalNumUnits` measures advertised availability, not vacancy.
